# 待ちを見逃さない島 — peek band 設計

2026-08-24。閉じた島の情報設計を作り直す。

## 問題

島を使っていて「何が起きているか一目で分からない」。原因は見た目ではなく、**閉じている間の情報量がほぼ空**なことだった。

閉じた島が伝えているのは2つだけ。

| 出ているもの | 中身 | 実装 |
|---|---|---|
| バーのグリフ | `waiting` / `running` / `idle` の3状態 | `AppModel.islandClosedMode` |
| 右スロット | `×3` か、色タイルが3個 | `AppModel.islandClosedRightSlotContent()` |

**誰が・何を待っているかはゼロ**。中央ラベルは `layout == .external` のときだけで、MacBook のノッチ上では出ない（`IslandPanelView.swift:363`）。

さらに2つ。

- **待ち時間がどこにも出ていない。** `RelativeDateTimeFormatter` はフック設定画面でしか使っていない。30秒待たせているのか30分なのかが読めない
- **待ちに気づけるのは一瞬だけ。** 待ちが出ると通知モードで島が開くが（`notchOpenReason == .notification`）、`autoCollapse` で畳まれる。見逃すと閉じた島の色に戻り、そこには何も書いていない

比較対象（Vibe Island, https://vibeisland.app/ 2026-08-24 取得）は、展開時に「`Claude asks` / 質問文 / `⌘1 ⌘2 ⌘3`」を出し、一覧の各行に `28m` を入れている。差はこの2点に集約される。

## 設計

閉じた島に**帯（peek band）**という状態を足す。「気づく」と「読む」を分ける。

### 状態は3つ

```
静穏          ╭──────────╮
        ──────┤  ≡≡≡  ×2 ├──────      いまのまま
              ╰──────────╯

帯            ╭──────────────────╮
        ──────┤ ◆ claude   2分 ×2 ├──────   待ちがある間ずっと
              ╰──────────────────╯

カード   ╭─────────────────────────╮
         │ ◆ claude が聞いている  2分 │      ポインタを近づけたとき
         │ Bash(rm -rf build/)      │
         │  [許可] [1回だけ] [却下] │
         ╰─────────────────────────╯
```

### 1. 帯に出すもの

左から、状態ドット・エージェント名・経過時間。複数待ちなら末尾に件数。

- **状態ドット** — 承認待ちと質問待ちで色を変える（既存の `statusTints.waitingForApproval` / `waitingForAnswer`）
- **エージェント名** — `claude` / `codex`。セッション名ではない。セッション名は長さが読めず、ノッチ横の限られた幅で切り詰めると意味が消える
- **経過時間** — `2分`。60分を超えたら `1時間`。**秒は出さない**（1秒ごとの再描画は常時背景アプリに見合わない）
- **件数** — 待ちが2件以上のときだけ `+2`

MacBook のノッチ上では物理ノッチの左右に振り分ける。左に「◆ claude」、右に「2分 +2」。中央は物理的に使えない。外部ディスプレイでは1行に収める（既存の `V6ClosedLayout` の分岐に乗る）。

### 2. 帯は答えるまで消えない

`autoCollapse` が畳むのは**カードだけ**にする。帯は待ちが解消するまで残す。

解消の経路は答えることだけではない。エージェントが諦める / セッションが終わる / 自動応答ルールが答える、のすべてで帯は消えなければならない。**同じ「出口を全部数える」問題を、カメラの開けっぱなしで一度踏んでいる**（`fail-open-state-drift`）。あのときと同じ形で、イベント適用の入口に `defer` を置いて全出口で再評価する。

### 3. 近づけたら開く

既存の hover open をそのまま使う。帯にポインタが乗ったらカードが展開し、離れたらカードだけ畳んで帯に戻る。新しい操作は増やさない。

### 4. 経過時間の出どころ

`session.updatedAt` をそのまま使う。**新しいフィールドは足さない。**

待ち状態のセッションはユーザーにブロックされていてイベントが来ないので、待ち始めの `updatedAt` が動かずに残る。`SessionState.swift:48-51` のコメントがこの性質を明示している（「待ちのセッションは *ユーザーにブロックされているから* idle」）。

実装時に1つだけ確認する: **待ち状態の間に `updatedAt` を動かす経路がないか**。あるなら、そのときだけ `waitingSince` を足す。

### 5. 更新の頻度

1分に1回。`UnifiedBars` が既に持っている `TimelineView` の仕組みに乗せる。専用のタイマーは足さない。

## やらないこと

- **キーで即答（⌘1/⌘2）は今回入れない。** 帯が定着してから足す。`rm -rf` を読まずに ⌘1 する事故が先に起きる。帯の上に後から足せるが、逆はできない
- **常時大きい表示にしない。** 待ちがないときは今のまま黙っている
- **セッション名を帯に出さない。** 幅が足りない

## 分割

純関数とビューを分ける。テストできるのは前者だけなので、判断は全部そちらに置く。

| 単位 | 責務 | 置き場 |
|---|---|---|
| `IslandPeekBand.content(for:now:)` | セッション一覧と現在時刻から、帯に出す内容（または nil）を決める | `OpenIslandCore` |
| `IslandPeekBand.elapsedLabel(_:)` | 秒数 → `2分` / `1時間` | `OpenIslandCore` |
| `V6PeekBandView` | 受け取った内容を描くだけ | `OpenIslandApp/Views` |
| `V6ClosedPill` の拡張 | 帯の有無で幅を決める（既存の fluid layout に乗る） | `OpenIslandApp/Views` |

`IslandPanelView.swift` は既に 3,538 行ある。**帯のコードをここに足さない。**

## 検証

- `content(for:now:)` — 待ちなし → nil / 承認1件 / 質問1件 / 複数 / 待ち以外のセッションが混ざる、の各ケース
- `elapsedLabel` — 0秒・59秒・60秒・59分・60分・25時間
- 帯が消える経路 — 答えた / エージェントが諦めた / セッション終了 / 自動応答、の4つすべてで帯が消えること
- 幅 — 最長のエージェント名＋`59分`＋`+9` でもノッチ幅を超えないこと

## 前提（確認せずに置いた）

- 帯の高さは閉じたピルと同じ。縦には伸ばさない
- 帯に出すのは**最も古い待ち**1件。新しい方ではない（放置されているものを出す）
- 待ちが `running` に戻ったセッションは帯から消える
